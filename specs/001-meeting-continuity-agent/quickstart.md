# Quickstart & Validation Guide: Meeting Continuity Agent

**Feature**: [spec.md](./spec.md) | **Contracts**: [contracts/api-contracts.md](./contracts/api-contracts.md) | **Data Model**: [data-model.md](./data-model.md)

This guide describes how to stand the feature up and prove it works end-to-end. It intentionally
contains no implementation code — see `tasks.md` (generated by `/speckit-tasks`) for build steps.

## Prerequisites

- A running Hindsight API server (self-hosted via `hindsight-all`/Docker, or Hindsight Cloud) and
  an API key.
- A Groq API key (primary LLM provider) and, optionally, Microsoft Foundry credentials if
  exercising the alternate provider.
- A Google Cloud OAuth client (Calendar + Meet scopes) if validating Phases 3–4.
- A Sarvam API key if validating Phase 5 (Batch STT) or Phase 7 (Realtime STT).
- Node.js + a Python environment matching whatever versions are pinned in
  `research.md`'s Technical Context once finalized in `plan.md`.

## Environment

Copy `.env.example` to `.env` and set, at minimum:

```
HINDSIGHT_API_URL=...
HINDSIGHT_API_KEY=...
LLM_PROVIDER=groq            # or "foundry"
GROQ_API_KEY=...
# FOUNDRY_ENDPOINT / FOUNDRY_API_KEY only if LLM_PROVIDER=foundry
GOOGLE_OAUTH_CLIENT_ID=...
GOOGLE_OAUTH_CLIENT_SECRET=...
SARVAM_API_KEY=...           # optional until Phase 5
```

No secret above is ever exposed to the frontend build — the frontend only ever calls the backend's
own `/api/*` routes.

## Run

```
# Backend
cd backend && uvicorn main:app --reload

# Frontend
cd frontend && npm run dev
```

## Minimum Viable Validation (Phases 1–2 only — no Google/Sarvam needed)

This is the core Hindsight demonstration and should be validated first, before any external
integration work begins (Constitution Principle XV: prefer the simpler path that proves the memory
story).

1. **Create relationship + Meeting 1** via the "Meeting Capture" view, pasting the notes below (or
   `POST /api/meetings` + `POST /api/transcripts/upload` with `transcript_text`):

   > Meeting with Acme Corp, 2026-01-10. Client (Priya) says the budget is strict — under $50k.
   > Client wants deployment before October. Priya prefers short, concise technical proposals, not
   > long documents. I (the user) promise to send an architecture document by next Friday.

2. **Trigger analysis** (`POST /api/transcripts/process`). Expected: `AnalysisResult` contains a
   `commitment` (owner = the user, deadline = "next Friday"), a `preference` (concise proposals), a
   `requirement` or `context` item (budget under $50k), and a `context`/`requirement` item
   (deployment before October). `had_durable_content = true`.

3. **Retain** (`POST /api/memory/retain`). Expected: `retained_item_count >= 3`,
   `resolved_commitment_count = 0`. Confirm via `GET /api/relationships/{id}/memory` that the items
   appear, each with `source_meeting_id` pointing back to Meeting 1.

4. **Prepare (stateless)** — `POST /api/meetings/{id}/prepare` with `mode: "stateless"` for a
   *second*, not-yet-created meeting request. Expected: a generic brief with no `source_meeting_id`
   citations and no mention of the budget/deadline/preference from Meeting 1.

5. **Add Meeting 2** with notes that reference cost again and introduce a security requirement,
   then repeat steps 2–3 for it.

6. **Prepare (memory-enabled)** — same request as step 4 but `mode: "memory_enabled"`. Expected: the
   brief's `confirmed` section includes the budget concern, the October deadline, the proposal-style
   preference, the user's outstanding architecture-document commitment, and the new security topic —
   each with a `source_meeting_id`/`source_meeting_title`/`source_date` citation. This is the
   before/after comparison required by Constitution Principle II and spec.md Story 3.

7. **Add Meeting 3** whose notes state the architecture document was sent (satisfies the earlier
   commitment) and change the deadline discussion. Retain it, then prepare again. Expected:
   `resolved_commitment_count = 1` from the retain call in this step, and the new brief's
   `user_commitments` no longer lists the architecture-document item as outstanding — confirming
   FR-010's status transition.

8. **Ask a free-form continuity question** — `POST /api/meetings/{id}/prepare` with
   `question: "What did I promise last time?"`. Expected: a grounded `Answer` citing Meeting 3 (or
   Meeting 1, if asked before step 7), `grounded: true`.

9. **Ask about something never discussed** (e.g., `question: "What did they say about our
   competitor?"`). Expected: `grounded: false` and an explicit "not enough information" response —
   never a fabricated answer (FR-016, Constitution Principle VI).

If steps 1–9 all pass, the core Hindsight-driven memory demonstration (constitution Principles I,
II, X) is validated without any Google/Sarvam dependency.

## Extended Validation (Phases 3–7)

- **Calendar**: `GET /api/calendar/upcoming` returns a real upcoming event; selecting it and
  preparing a brief resolves `relationship_id` from attendee email/name matching.
- **Meet transcript fallback**: simulate a conference with no available Meet transcript; confirm
  the UI falls back to recording upload → transcript paste → manual notes without erroring (stack
  instructions §5).
- **Sarvam Batch STT**: upload a short multi-speaker recording; confirm `TranscriptSegment.speaker_id`
  values differ per speaker and `confidence` is populated.
- **Conflict surfacing**: retain a meeting stating a "2-week estimate," then a later meeting stating
  a "4-week estimate" for the same topic; confirm the next brief's `conflicts[]` array contains both,
  with the recommendation to confirm (research.md §11).
- **Failure handling**: point `HINDSIGHT_API_URL` at an unreachable host and repeat step 6; confirm
  `/prepare` returns the documented `502 hindsight_unavailable` degradation rather than a stack
  trace, and the UI surfaces a clear error (FR-022).

## Out of Scope for Validation

Per spec.md's Out of Scope section and Constitution Principle XIII: multi-user login flows,
enterprise SSO, CRM/email integrations, and a mobile client are not part of this guide and should
not be validated as part of this feature.
